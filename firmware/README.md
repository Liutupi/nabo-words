# 《NABO 单词护照》独立固件

按 `DESIGN.md` 的计划，这是只装这一个游戏的离线固件（不带小智），整片 Flash 和全部内存给它用，对战走 ESP-NOW。
目前完成到 **M2：纯逻辑模块**，还没有 ESP-IDF 工程、渲染和设备代码。

## 目录

| 路径 | 内容 |
|---|---|
| `main/words/nabo_words_rng.h` | mulberry32 随机数和洗牌，和原型逐位一致 |
| `main/words/nabo_words_db.h` | 词库接口（单词、释义、某个拼写是不是词库里的词） |
| `main/words/nabo_words_model.c/.h` | 记忆盒、每日题单（按时间预算）、学习日与打卡、结业考、成就、小卖部 |
| `main/words/nabo_words_quiz.c/.h` | 题型、干扰项、补字母、今日学习队列、结业考、答题后的处理 |
| `main/words/nabo_words_battle.c/.h` | 对战出题范围、出题、计分、Elo、段位、对局结算（含防刷分） |

逻辑模块不依赖屏幕、声音和 RTOS，学习日由调用方推进。只用整数运算（ESP32-C3 没有浮点单元）。

内存：状态 `nw_state_t` 约 22.6 KB（7500 个盒子 + 7500 个到期日），排题单时的临时数组 `nw_work_t` 30 KB（用完即可释放），学习队列 `nw_session_t` 约 5 KB。

## 和原型对拍

原型（`prototype/core.js`、`quiz.js`）是规则的标准答案。改规则的顺序：先改原型 → 重录轨迹 → 改 C → 跑测试。

```sh
node tests/words_host/record_golden.js     # 从原型录轨迹到 tests/words_host/golden/
python3 tests/words_host/test_words.py     # 编译 C 逻辑模块，逐步重放核对
```

轨迹覆盖四种学习习惯（稳定、偷懒、速成到毕业、吃力），共 1600 个学习日，每一天核对：题单、完整的学习和结业考队列（含答错后的重问）、
小卖部操作、对战出题和结算（含同一天打满 3 局后的防刷分）、翻天结果，以及当天结束后的状态摘要（各项数值 + 全部记忆盒的哈希）。
另有 Elo、计分、段位、单题出题、积压门槛、结业考解锁门槛的定向用例。

2026-10-21 结果：16317 步全部一致。故意改坏 19 条规则（复习间隔、积压门槛、价格表、干扰项范围、补字母排除真词、Elo 表、防刷分、
学习种子、及格线、解锁门槛等），每一条都能被测试抓到。

## 和原型不同的地方

- 同一天对战过的徽章只记最近 8 台（原型不限）；超过 8 台时最早那台的局数被挤掉。
- 毕业词的到期日在原型里是 1e9，这里是 0xFFFF；学习日用 16 位，够用 179 年。
- 学习队列最多 400 道题（原型不限），按每天最多 240 道复习估算有足够余量。
